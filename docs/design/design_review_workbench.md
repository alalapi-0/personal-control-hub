# 设计审核台规格

- 读者：所有者、Figma 设计者、Hub 界面实现者和验收者。
- 目的：定义一个用于选择视觉方案的最小界面，保持内容精简。
- 更新触发：用户调整审核体验、选择语义或支持设备。
- 版本：2；这是待实施规格，当前 Hub 没有这个界面。

执行边界见 [执行规范](ui_governance_execution.md)，持久化与版本约束见 [数据契约](ui_governance_data_contract.md)。

## 核心任务

用户进入某个项目/设计家族，看懂“现在是什么、候选改了什么”，比较后选择一个具体版本或提交修改意见；稍后能找到当时的选择及实现结果。审核对象是界面设计，不是漫画页、视频素材或其他项目的业务审核记录。任何按钮都不能修改这些业务记录。

设计模块入口只保留“项目/家族列表 → 方案比较”两层，嵌入 [Hub 成品](personal_control_hub_completion.md) 的项目管理界面。历史在当前项目内展开，不另建全站报表、十页控制台、任务调度和资产管理。无 UI 项目不造设计示例页面，但仍按 Hub 接入规格展示项目管理摘要。

## 比较页结构

| 区域 | 默认呈现 | 按需展开 |
| --- | --- | --- |
| 顶部 | 项目名、当前页面、设计版本、待选择/已选择/已过期状态 | 基线时间与来源、关联项目及共用范围。 |
| 方案导航 | 原版与 2–3 个候选缩略图、短名称、每款一句方向说明 | 字体/密度/组件外观等最多三项主要差异。 |
| 主画布 | 默认原版与当前候选并排，同视口、同内容、同状态 | 单屏放大、桌面/移动和关键状态切换，查看 Figma 原稿。 |
| 决定区 | 选择此版本、需要修改、暂不决定；一句可选反馈 | 明确的实施范围与授权记录，已获授权时展示来源。 |
| 历史抽屉 | 默认收起，显示最近决定摘要 | 谁在何时选择哪个精确版本、旧稿、验证和实施记录。 |

原版不可被候选覆盖；本地有对应快照，断开 Figma 后仍可对照。现有项目原版取自真实页面，若仅有代码证据，显著标注“未验证运行基线”。Hub 首次新建时明确显示“当前无图形界面”，参照最接近的现有 CLI/规划说明，不捏造原版截图；三个候选互相比照同一份新功能规格。

普通用户看到项目名和状态，不看到 raw hash、端口、堆栈、任务 ID 或完整日志。版本短标识和“基线已变化”提示保留，因为会影响选择。real/mock/dry-run/imported 在涉及数据可信度的预览旁用自然语言说明，例如“示例数据”“导入的设计稿”；诊断面可显示完整枚举。

## 功能约束与选择流程

1. 进入比较页时读取最新版本摘要，选择 UI 不改变被预览产品的状态。
2. 点击“选择此版本”保存不可歧义的项目/页面范围、baseline ID、candidate ID、内容 revision 和用户决定；保存成功才展示“已选择”。刷新和重启可恢复，失败保留输入并允许重试。
3. “需要修改”保存反馈并回到待修订，不生成假通过；新稿是新 revision，旧决定保留供回看但不自动适用于新稿。
4. 设计选择与实施授权分开记录。选择可以发生在没有实施授权时；UI 不暗中应用代码。若需要新增实施授权，先展示具体项目、候选版本和允许修改范围，再提供独立的授权动作。用户一条明确指令同时覆盖选择和实施时，可记录两件事，不要求重复点击。
5. 同一家族的选择仅覆盖明确列出的成员/页面，不能默认扩大到全名册。成员适配产生的实质差异仍需展示；未批准成员保持待定。
6. 可改选或撤回选择；保留决定事件，不删除历史。已实施设计的撤回不会自动回滚代码，回滚按新的明确请求处理。
7. 若来源变化、候选内容变化或并发决定冲突，拒绝静默覆盖，提示刷新和差异；不把“最后一次保存”自动当成用户最终意见。
8. 提供次要的“导出设计材料”入口，导出本地基线/候选快照、Figma 引用、版本、反馈/选择及适用范围，便于所有者后续使用。只导出获准的任务材料，不打包业务数据；校验工件哈希，缺失/过期或失败须提示，不静默混用版本。

首版只保存和展示授权记录，不建设后台自动改代码、自动通知其他 Agent 或发布的执行按钮。Hub 自身实现与必要的关联/视觉例外按执行规范处理；查看、选择或导出外部设计材料不会改外部项目代码。可程序化的校验、整理、导出不由 Agent 手抄。

## 视觉方向

在同一信息与功能规格上做三种有区别的初始方向，名称只是 brief，不预设用户偏好：

- **清晰编辑台**：中性背景、明确排版比例、细分隔，偏紧凑，适合经常对照。
- **专注画布**：主画布占更高比例、周边工具克制，适合图像/视频设计比较；不压低文字可读性。
- **柔和工作室**：温和色调、适度留白和轻量分组，适合长时间审核；不靠大面积装饰卡片撑版面。

不默认深色、不强制特定字体、不用渐变/玻璃效果替代层级。根据真实内容选字体与尺寸；中英文、长项目名、长反馈都需验证。每页一个主要决定，合理留白，减少重复标签与说明。独立项目可以选择其他方向；相关项目只共享已确认的视觉语言和适合的组件。

## 状态、输入与设备

| 场景 | 必需表现 |
| --- | --- |
| 首次无项目/无候选 | 区分“未纳入范围”和“尚未生成方案”，提供现有入口；不用假卡片填满。 |
| 加载/保存中 | 稳定占位、清楚反馈；禁用重复提交，避免跳动。 |
| 读取失败/Figma 不可用 | 保留本地快照、反馈草稿与重试；区分缺文件和连接错误。 |
| 基线/候选过期 | 明示过期，允许看历史，禁用对旧版本的新实施授权。 |
| 无实施权限/项目被占用 | 仍可查看与评议；只限制依赖权限的动作，并说明原因。 |
| 保存冲突 | 展示当前版本，保留本次输入，让用户在更新后确认。 |
| 撤回/改选 | 明确只影响设计决定，保存历史；不暗中触发业务操作或代码回滚。 |
| 键盘/读屏 | 顺序合理、焦点可见，控件有名称和状态；弹层关闭返回原焦点，不靠颜色区分结果。 |
| 减少动态效果 | 尊重 reduced motion，去除非必要过渡，保存/错误状态仍清楚。 |

桌面使用同尺度并排；手机默认单画布和原版/候选切换，保留可辨的标签、缩放位置和完整决定区，不将两张大图挤成无法阅读的列。断点由实际内容决定。阶段 B 默认用 1440×900 与 390×844 作为 Hub 取证视口，并补测 200% 缩放与长文本；这是本审核台测试条件，不传播为其他项目全局标准。可访问性默认以 WCAG 2.2 AA 为设计目标，除非项目有更严格要求；具体规则实现时核对当前正式规范。

## 审核台验收

用隔离示例完整走通：导入基线/候选 → 比较 → 提交反馈 → 选择 → 刷新/重启后回看 → 导出并核对材料 → 新 revision 使旧选择不再适用 → 改选保留历史。另验证重复请求幂等、冲突保存、文件缺失、Figma 离线、导出失败、手机/键盘操作。证明这些动作没有改动外部业务数据；真实来源覆盖按 Hub 成品规格单独验收。

视觉验收检查对齐、排版、信息层级、密度、长文本、状态和对比度；不以个人主观评分替代用户选择。截图只能证明渲染。完整 lane 结果、环境与候选身份按执行规范登记；本规格本身不代表验收已完成。
