# Hub 完成交付说明的编写要求

- 读者：完成 Hub 的执行者、所有者和未来维护者。
- 目的：Hub 验收完成后，留下一份无需依赖当前对话的交付说明。
- 更新触发：成品范围、运行方式、数据契约或交付要求改变。
- 版本：2；当前仅为编写规格，Hub 尚未因本文件而完成。

依据 [执行规范](ui_governance_execution.md)、[成品验收规格](personal_control_hub_completion.md) 和 [数据契约](ui_governance_data_contract.md)。后续使用 Cursor 或其他工具由所有者自行安排；本目标不操作、检查、配置、启动、等待或验证这些执行器，也不建立跨执行器调度协议。

## 形成最终说明的时机

先完成 Hub 成品和全部冻结范围内的真实管理连接，完成产品验收，再在 Hub 的 `docs/reports/` 形成一份带成品版本的最终交付说明。本文件不是最终交付实例；不提前生成“已完成”记录，也不把未完成的 Hub 必需项列为别人接手后再补的任务。

最终说明只需包含：

1. **交付内容**：Hub 成品身份、完成范围、项目接入 manifest 与逐项验收索引。
2. **如何运行**：真实启动/停止命令、必要依赖、访问入口、可重跑的刷新与校验命令。只停止本任务拥有的实例。
3. **如何使用**：项目/状态/来源/关系查询，设计比较、反馈、选择、回看和材料导出的一条简短操作路径。
4. **数据与设计**：唯一状态入口、registry/adapter、schema 版本、设计事件和日志位置、Figma 链接、冻结快照与已选版本；外部管理材料归并结果、实际入口切换和有依据的外部运行依赖；不复制完整外部仓库或业务数据。
5. **验证与边界**：实际运行的检查、退出码和证据；获准例外、已知限制、原有问题，以及外部项目和其他任务的保护情况。若发生必要的外部关联/视觉改动，列出精确范围、必要性和回归证据。
6. **维护与恢复**：数据保存/恢复方式、来源离线或版本漂移时的处理、task-owned 变更身份和回退说明；GitHub 交付分支、关键提交与远端核对证据。未同步单元不能冒充已完成交付。
7. **后续可选工作**：仅记录所有者未来可能继续的事项与必要背景，不派发任务、不安排执行器、不代替所有者确定其后续流程。

## 交付文档检查

由当前执行环境核对路径、命令、版本引用和证据链接，确保实际可用且状态表述准确。文档不能声称未执行的验证已通过；不以其他软件的兼容性、接管或启动演练作为 Hub 完成条件。

完成后将成品与交付说明指针记录在 Hub 的唯一 `STATE.yaml`，收齐本任务子 Agent，保持其他项目与任务原状。此时可以结束已达成的 Goal，无需等待任何后续执行者。
