## 3. 主目标、代码边界与范围

1. **完成 Hub 本身。** 建立必要的 Hub 项目内协议和最小路由，处理关系/设计家族、并发隔离、证据与决定语义；实现项目列表/详情、状态/下一步/来源、刷新、设计比较选择与历史、材料导出和程序化读写校验。项目内控制面变更由 Root 按 GOVERNED 流程处理，不默认修改全局 agents、模型、权限、Skills 或插件配置。
2. **打通 Hub 的真实管理连接。** 查看允许的外部状态来源与现有 UI，按证据建立关系，在 Hub 内完成 registry/adapter/投影与展示。冻结范围内逐项验证真实读取和刷新，不能以名称登记、mock 或单试点代替。
3. **主实现只落在 Hub，外部业务项目默认只读。** 用户允许的外部关联代码和视觉代码属于有限例外：必须直接服务本目标、无法合理地由 Hub 内适配替代，且已明确精确仓库/文件或符号、具备独占隔离范围并可验证不干扰其他工作。禁止修改外部业务功能、算法、数据处理、业务状态及其他 Agent 正在推进的代码。不能借“关联”或“视觉”重构业务。不能隔离时保留 Hub 内适配或设计材料，不触碰外部工作区。经核实属于 Hub 的外部管理材料归并另按第 10 节，不扩大业务项目权限。满足已有授权和上述条件时不逐文件重复索权；新的明确禁止边界不得绕过。

Hub 成品、冻结范围内的真实管理连接和设计记录是必需交付。外部项目改版与代码实施不属于完成前提，也不安排其后续开发。完成后留下可独立阅读的交付说明即可；不创建跨执行器治理，不等待其他工具接手。

首次启动从 registry 冻结接入清单，覆盖每一条项目记录，并单独判定 UI 范围 `in_scope / no_ui / deferred / protected / unresolved`。没有 UI 不等于不需要被 Hub 管理。名单 ID 只引用 registry，不复制路径维护第二份名册。禁读、未登记或尚未确认对象不能默认为可扫描/可设计；存储治理的专用豁免也不能直接解释成 UI 或项目管理的永久豁免。逐项查明当前有效边界。接入范围变更和无法接入的例外须明确记录所有者决定或已有适用策略，不得自行排除困难项目以达到全量完成。接入判据见 Hub 完成交付规格。

视频生产、内容审核、媒体播放只是勘察线索。区分“业务链路有关”和“适合共用视觉系统”：共用人物/素材管线不必共用播放器布局；不同技术栈可共享排版、颜色和状态语言，不强制共享代码包。关系记录包含双方 ID、关系种类、证据来源、共同任务/交互、差异和不共享部分。未确认关系保持独立；正式 program link 仍按现有提议/确认规则处理。

## 4. 视觉改版的功能不变量

每个现有界面先形成基线记录：源码身份、相关 dirty 内容哈希、运行版本、页面/路由、角色权限、任务入口、动作/快捷键、输入默认值与校验、状态转换、保存与恢复、数据字段语义、请求/副作用、支持设备及未验证项。

允许调整颜色、字体、图标、间距、边框、视觉层级、组件外观和不改变任务路径的布局；允许响应式视觉修正。不得增删功能、改审核结论/状态含义、隐藏必要字段或操作、改路由/快捷键/默认值/权限/接口/业务算法。精简指减少重复说明和装饰，不指删能力或强行统一信息密度。DOM/模板可因布局调整，但事件与语义契约必须可追溯一致。业务逻辑与视图混在一文件时，按符号和行为审查，不能只看扩展名。

发现外部既有功能问题仅记录来源和影响，不能作为借口修业务；使用隔离预览/fixture 验证 Hub 或调整 Hub 适配。Hub 本身阻断成品的缺陷在明确写入权后解决。截图不能代替交互、持久化或数据正确性证明。

## 5. Codex 交付阶段与自举

| 阶段 | 最小可审核产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：取证与协议 | Hub 现状、全范围接入清单、关系证据、功能基线、Hub 项目内协议 | 来源可追溯；范围/边界明确；不影响其他任务。 |
| B：数据与 Hub 设计 | 可执行接入/校验基础，同一完整 Hub 规格下的 2–3 个 Figma 方向，默认 3 个 | 隔离验证；本地预览与节点对应；用户选定版本。 |
| C：Hub 成品与接入 | 项目管理及设计审核界面，逐项目真实摘要接入、关系展示、刷新/错误/来源/历史 | 全范围连接有逐项证据，状态真实、决定持久化；完成独立验收。 |
| D：设计管理闭环 | 现有 UI 证据、Figma 候选、Hub 比较/反馈/用户选择、历史和材料导出 | 版本/决定可追溯，共享/独立规则及漂移/冲突已验证；不要求外部代码实施。 |
| E：完成交付 | 完整 Hub、全范围连接证据、运行/维护/恢复说明 | Hub 必需项验收完成；独立交付说明的真实路径与命令已核对。 |

阶段可在依赖满足时交叉推进。设计管理闭环使用获准的真实 UI 观察作为来源，在 Hub/Figma 中验证候选与决定，不改动外部业务。共享家族与独立项目规则都应覆盖；某类真实不存在时用明确标为 mock 的夹具验证分支。代表页面/fixture 只验证方法与异常分支，不能代替全部冻结项目的真实管理接入。

审核台尚未存在时，阶段 B 在 Hub 保存脱敏导出的本地比较材料，用 Figma 链接和当前对话接收首次选择；历史选择按数据契约导入后续审核台。不得要求先做完审核台才能选它自身的设计，也不得借自举先实施所有候选或搭临时完整应用。

设计候选提供实际可比较的排版、密度和组件语言变化，不能只是换主题色。同一视口、数据、任务状态对照；原版始终保留。推荐由 Agent 说明理由，决定由用户作出。一个方向失败后针对反馈修订，不能无止境添加新方向。

## 6. Figma 路径

启动时检查可用工具和当前授权，读取 `ui-design-governance`。真正调用 Figma 时按任务加载 `figma-use`、`figma-generate-design`；新文件先加载 `figma-create-new-file`，新组件/变量加载 `figma-generate-library`，实现 Figma 设计前加载 `figma-design-to-code`；原生平台按对应技能路由。这里不固化插件缓存路径或 API 参数。

先查产品字体、token、组件、Code Connect 与可用设计库；改风格时记录有意改变的视觉项。新文件缺少设计库时建立本轮必要的本地变量/组件，不虚构库。保留原版与候选为可编辑版本，记录 file key、node ID、版本/导出哈希；默认只写任务专用文件/页面，不覆盖已有设计。已有 Figma 资产只在授权范围内修改。

Figma 是外部服务。仅发送本轮获准的界面结构和合成/脱敏素材，不上传私有原图、真实审核内容、凭据、完整仓库或数据集。有图的页面可用隔离 fixture 捕获；不能直接捕获带私有内容的正在运行页面。工具未连通或无授权，先完成本地规格与取证，标记相关 Figma 步骤未验证，不拿本地草图冒充 Figma 成果。连接故障只阻塞相关阶段，不降低最终要求。

## 7. 与其他任务同时推进

- Root 在写入、fetch、Git 操作前用原生任务状态和既有归属约定确认具体文件所有权；共享 cwd、进程、idle/notLoaded 或没有锁均不能单独证明冲突或无冲突。只挂起未解决的重叠文件组，继续独立工作；不建锁服务，不取消、暂停、重命名其他独立任务。
- 跨项目仅可并行只读勘察；修改、验证、状态更新和 Git 操作一次只针对一个仓库，Root 负责共享写入。子 Agent 只领取不重叠范围，不自行再派生。
- Hub 实施或必要的外部关联/视觉例外，均须先确定独占 checkout/目录及文件/符号允许清单；外部推进中的工作区不写。独立 worktree 仍共享 Git 元数据，创建/fetch/索引操作须可安全串行；不能确认时继续只读取证和 Hub 内工作，不影响其他任务。
- 共享 checkout 的未提交业务改动不 stash、不 reset、不复制成备份、不猜测合并。默认从已知提交建立隔离基线；若候选依赖他人的未提交功能，等待该功能形成可用交接版本。相关 diff 只在实际需要时定点读取。
- 预览使用独立端口、测试数据和输出目录；不重启/杀死原服务，不触碰正在跑的批处理、真实数据库和审核记录，不安装共享依赖或修改锁文件以配合新视觉框架。
- 基线保存 HEAD、UI/接口/依赖关联文件指纹、相关 dirty 指纹。候选、用户选择、应用前分别重查；相关指纹变化立即标记 stale，保留旧版本并生成新候选验证。无关文件变化不要求全部重做；不冻结整个项目进展。
- 设计、接入和验证记录全部回 Hub；仅发生必要且获准的外部关联/视觉例外时，外部仓库保留精确实现和项目要求的最小材料，不另建竞争的设计日志。回写 Hub 前重新确认 Hub 写入范围。
- 应用、合并、推送、发布是不同效果。选择方案不自动授权任何一种；具体实施授权已覆盖时不重复询问。不得因为验收通过继承旧轮 Git 权限或自动覆盖功能开发分支。

## 8. 续跑、等待与唯一状态

规范不是进度表。`STATE.yaml` 保持唯一 Hub 当前状态权威，外部 STATE 仍管理其业务进度。真正启动时先确认 Hub 状态写入权，在既有 `current_work` 中登记本任务、规范/证据索引、当前单元和唯一下一步；不得覆盖其他未完成 Hub 工作。保留存储项目状态和历史指针，遵守 8192 bytes 启动包上限，详细证据放索引外。必要的 Hub 路由/状态结构调整在本目标内完成并独立审查。

每轮读默认启动包，并参考本规范中当前单元需要的部分，再只读相关基线、候选和最近有效证据。新任务或实质扩域时做一次交付/验收/排除项判断，正常步骤不反复规划。完成一个闭环后更新现有状态中的证据指针、完成情况和唯一下一步；保留必要版本、失败指纹及有效结论，不机械新建每轮报告、备份或重复台账。无相关变化不重跑相同检查、重审同一候选或重新派发已完成子任务。两个连续无进展尝试后改变方法；仅已证实的瞬时故障允许同态再试一次。

等待用户选择、实施授权、写入权或工具恢复时，只挂起依赖项并展示具体项目/版本；可继续其他独立取证或设计。所有独立工作已尽时保存恢复点，等待输入，不忙轮询、不代选、不反复生成方案。原生 Goal 的状态严格按当时工具规则处理：未达成不得 complete，blocked 只在其规定条件满足后标记；不编造预算、计数或运行状态。用户明确暂停/停止时，停止本任务的精确子 Agent 和外部效果，保留恢复信息，不影响其他任务。

## 9. 验证与完成

每个执行单元首次写入前运行一次 `python3 scripts/auto_advance_runner.py --mode check`，它已包含 gate，不另跑 `agent_gate.py`；相关输入未变时复用检查。这不授予权限。控制面变更由 Root 写入，冻结精确语义候选后做一次 fresh Judge 审查及 Governor 决策。PASS、决定和下一步元数据在审核内容身份外，更新它们不触发重复审核；不要对包含自身 hash 的记录再计算身份。真实语义变化才重新登记和适用审核。文件/实现/测试路径可自适应，不因偏好重构或正常修复就修改合同；冻结目标、边界、外部效果、验收或预算变化才修订。普通产品改动按实际风险选 DIRECT/REVIEWED。

按照 UI 技能完整验收量表，分别记录功能、视觉、适用的桌面/移动、console、network、隔离和实现适配结果；用 `PASS / FAIL / UNVERIFIED / NOT_APPLICABLE`，不适用必须有产品依据。使用隔离 fixture 测用户主流程、状态恢复、错误/空/禁用、键盘焦点、可访问性、响应式与 reduced motion。任何本轮必需项未验证不能计为总体通过。

Goal 完成必须同时具备：[Hub 完成交付规格](personal_control_hub_completion.md)全部必需项通过；冻结范围真实接入/关系逐项具备证据；Hub 项目管理、刷新和设计比较/反馈/选择/历史/导出真实可用；读写、校验、过期检测和汇总可由程序完成；Hub 已实现用户选定的 Figma 方向并通过验收；第 10 节管理材料归并与第 11 节 GitHub 交付完成；其他项目的业务和正在推进的工作不受影响；验收后按[完成交付说明规格](completion_handoff.md)写好交付文档。用户必需决定或接入权限未解决时，不得虚报完成。

完成本 Goal 只以 Hub 成品与项目关联为准；不要求任何外部项目先改完 UI，不操作或等待后续执行器。业务数据迁移、真实调度、飞书和发布平台不属于本目标；项目管理摘要的全范围贯通属于必需项。

基线检查失败单独报告，准备轮不修复现有代码。未来实现中，阻断 Hub 成品/接入的本仓库缺陷属于需要明确归属后修复的工作；无关存储治理和外部业务缺陷不顺带修改。文档准备的验证不能宣称上述未来 UI 已通过。

## 11. 每个验收单元同步 GitHub

授权对象是本 Hub；Root 在每个恢复后 accepted 里程碑/治理轮收口时做一次任务范围明确的 commit，并正常推送该仓库当前跟踪分支，再确认远端包含该精确提交。验证通过不自动等于 accepted；控制面单元先完成适用独立审核。无变化或仅重复观察不造空提交，也不为每次工具调用提交。

准备时核对的参数：remote 为 `origin`，分支为 `agent/governance-closure-20260812`，upstream 为 `origin/agent/governance-closure-20260812`。每次交付前核对实际配置、归属和目标仍正确；不改 remote、不自动合并 main、不强推或改写历史，不部署/发布。凭据使用现有 Git/OS 配置，不读取、复制或输出秘密。

恢复首个交付单元先核对暂停前尚未同步的成果。依据已验收候选与当前归属认领需要交付的文件/片段，复用有效证据；TC4 等未验收内容先收口。全局治理与其他任务的 dirty 文件不因同处工作区就加入本提交，禁止 `git add -A` 式无差别收集。若必要依赖属于他人，先定位精确依赖/移交版本，仅挂起受影响交付，继续独立建设。

交付顺序：相关检查与验收 → 审阅精确 task-owned diff/暂存候选及敏感内容 → commit → 正常 push → 核对远端 commit。必要远端同步和冲突处理仅限本仓库已授权范围，保护未提交内容；结果不确定先查远端再重试。推送失败保留已验证本地提交与精确原因，不能把 GitHub 同步记为成功。网络/凭据/受保护分支阻塞只挂起交付依赖，不伪造验收或自动扩大权限。状态与交付说明记录必要提交/证据指针，不再加一套同步台账。
