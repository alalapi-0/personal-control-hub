# 项目数据发布与同步：长期执行路线 v3

读者：所有者、Codex、Cursor及其他项目维护者。用途：后续长期实施的共同规范；目标、数据契约或阶段验收改变时更新。静态阶段/项目映射在 data/roadmap/project_data_v3.yaml；当前执行事实只在 STATE.yaml。

## 激活与既有成果

本轮只准备计划和Prompt，不启动实施。STATE的v2状态、完成事实、费用/凭据限制、失败和恢复点继续保留。阅读、提交、同步本文件不切换执行版本；只有所有者明确发送v3启动正文才激活。旧任务的未解决项不得被计划覆盖，也不得因新计划重跑已经有效的验证。

激活时复用all_projects_governance这个唯一状态条目，记录v3计划版本、当前阶段/项目/验收单元及既有证据引用，保留累计用量与历史轮次口径；不要新建Goal调度器或第二份当前状态。STATE中的prepared_plan只是入口，不是v3完成证明。

v2已有采集器、数值/变化查询、账本、Git与GitHub读取、部分主分支交付和真实数据副本验证是可复用基础。23/24来源覆盖等已有结论仅是v2事实，不证明v3项目导出、启动同步、版本化审核已完成。空来源项目、无Git、漫画实际重做、历史CI失败继续保留；不因最后一个项目缺源而反复等待、重查其他已完成项目。

## 目标与边界

项目权威源 → 项目导出函数 → 标准快照 → Hub脚本同步/校验 → 共享API补充 → 数值汇总和历史 → 可选模型分析。关闭Agent、模型和MCP后，采集、同步、校验、查询和管理规则仍可运行。模板声明统计口径，函数计算，快照承载结果。

项目侧复用hub.connection.yaml作为稳定声明，拟议.hub/status.json作为机器生成快照；最终路径在契约阶段确认且只保留一套。共享Schema、指标定义和通用导出/Git代码集中维护，项目只提供映射或小型业务函数。模板/代码入Git，可重建快照与缓存精确忽略；原始数据不能被当缓存删除。

Hub导入模块只读取标准快照，不理解子项目数据库表或任意业务目录。启动协调脚本可以调用项目明确登记的纯统计导出入口；计算在项目边界执行，不运行生成、测试、部署或提交。GitHub等公共数据用Hub共享适配器查询，不要求每个项目重复实现API统计；本地未提交数据由共享本地Git函数提供。

本阶段不生成图表、不做UI改造；可以准备展示字段、规则和现有启动入口的同步连接。飞书只保留禁用的本地映射。不操作任何编辑器/账号运行时、全局Agent/模型/权限配置，按本路线迁移独立子项目，不调用未授权付费生成，不自动创建仓库/远端。

登记以data/registry/external_projects.yaml为权威；云项目排除，removed_local禁扫描/读写/重试。空项目、离线、缺源、无Git各有处置，保留原分母；未知不能改写成0或验收通过。Codex/Cursor/人工来源不决定项目范围。

## 统一审核阶段、返工与验收词义

一审、二审是业务实际审核阶段，后续可以配置真正二审。stage_id是本路线阶段，execution_round是逻辑执行轮；业务review_stage、submission_attempt、rework_count、candidate_revision分别表示审核阶段、同阶段提交次数、重做次数和候选版本，不能共用一个round字段。

最小关联键为project_id、item_id、candidate_revision/content_hash、review_stage、submission_id、decision_id；审核、自动验证、验收和交付均绑定明确对象与版本。描述文字由这些字段生成，不能反过来由Agent猜状态。

| 时点 | 保留的事实 | 当前流程与允许动作 |
| --- | --- | --- |
| v1首次送一审 | 一审/第1次提交，绑定v1 | 待一审→一审中；显式送审后才进入审核队列 |
| 一审不通过 | 保留v1一审未通过、意见和决定ID | 待重做；不能改回普通待审，也不能变成二审 |
| 领取/执行重做 | 当前任务引用退回决定、旧版本和重做范围 | 重做中；生产失败保留本次尝试，不跳过重做 |
| 新候选v2生成并持久化 | 保留v1与失败意见，记录新版本及重做结果 | 待提交一审；还未送审时不得进入审核队列 |
| v2显式提交 | 一审/第2次提交，绑定v2 | 新版本待一审→一审中；提交次数不改变审核阶段 |
| 一审通过 | 一审批准仅适用v2 | 若项目配置了二审且前置条件成立，才进入真正二审；否则进入明确的下一验收步骤 |
| 验收/交付 | 各自记录版本与凭据 | 审核批准不自动等于最终验收或交付；不继承旧版本结论 |

流程必须在业务项目中修复：实际退回决定幂等创建一个重做任务，项目完成重做和提交后才允许重新进入对应审核队列。导出器/Hub导入只读结果；导入旧issues、刷新页面、修改显示文案都不能触发业务任务或冒充回流已修复。

production_state与review_state/decision、validation、acceptance、delivery分开。新版本必须重新满足required_review_stages；返工后从首个失效的必需审核阶段开始，无法证明已有阶段对新版本仍有效时，从首个必需审核重走。二审退回的回流目标由明确规则决定，不能自动绕过一审。最终验收不通过也回到明确重做入口，保留原验收决定。

稳定decision_id/任务键与事务或等效机制避免重复入队；重复事件返回既有结果，迟到的v1决定不能覆盖v2或重新触发返工。网络重试、worker失败次数、重做任务数、送审次数分别计数。只有正式新提交才增加同阶段提交次数；Git commit不是业务送审的前置条件。

仅复核误判且未修改作品时，明确标记reconsideration并引用原版本，不能算已完成重做。明确放弃的对象保留处置，不无限返工。旧数据中的pending/approved/issues、最大版本号和修改时间都不能证明审核阶段、提交次数或最终验收；缺失字段保留legacy_unknown及原始记录。迁移不得重写历史、伪造二审或从聚合数生成任务。

首个回归使用真实失败ID的隔离副本验证：一审未通过→待重做→领取→新版本→重新提交一审→一审通过→按配置进入真正二审/验收；覆盖重复、迟到、并发与中断恢复。真正业务重做缺费用/凭据授权时保留未完成，不用mock、改状态或改名称当闭环完成，并继续独立数据单元。

## 外置盘迁移与路径连接

按所有者最新要求，后续实施将除Personal Control Hub外的独立本地项目放在外置盘；新迁入项目默认根为/Volumes/AI_WORK_SSD/Projects。已在该外置盘其他位置且入口有效的项目不为统一目录名再次搬运。Hub仓库及内部治理模块留本地、不拆仓；removed_local不探测或恢复。

准备期仅核对根路径与Git所属：21个独立项目已在外置盘，manga-localizer仍在内置盘；storage_governance属于Hub仓库内部模块。实施时只复核变化和目标可用性，不把这份观察当永不过期的事实。

采用整项目目录迁移，包含Git元数据、未提交/未跟踪工作与项目私有数据；不能只从GitHub重新clone后丢弃本地独有内容。先用脚本检查根目录身份、目标容量/冲突、实际写入者、挂载和必要连接。普通文件无需模型逐个阅读；由复制工具和必要的程序校验给出条目/字节/失败汇总，必要时对关键数据或疑点做校验，不为每个文件生成报告。

跨盘先复制到明确目标并验证，再切换registry、启动/导出入口和必要路径；在目标可用且独有数据完整后移除原项目源目录以完成迁移，不无期限留双份。外链保留并验证目标，不跟随复制已在外盘的素材；Git worktree/gitdir指针按其实际结构使用正确迁移方式，不把链接文件当完整仓库。活跃数据库/写入者需一致性复制或短暂协调，只影响当前项目，不停止无关任务。

优先修复权威路径和实际消费者；必要时在旧路径建立明确的兼容连接，但只保留一个真实项目根。现有路径守卫若拒绝新根，定位并最小修复其允许的真实根及测试，不删除守卫或伪造位置。目标存在冲突、盘未挂载或完整性未确认时保留原数据/恢复点，不覆盖或先删源。

原工作区已有的存储参数/适配器/状态尚未包含在本次基线main，V3-01先核对并接入必要的有效版本；不能在缺入口时绕过约束或复制整套历史。迁移单元复用现有storage_governance参数、适配器和唯一执行STATE；Hub只引用其结果，不重开旧全盘治理或复制第二套迁移账本。执行前只按该入口读取当前项目所需规则；本次授权是项目整目录迁移，不自动继承历史“清理所有缓存/历史”的扩大删除范围。

目录移动本身不产生Git内容差异；路径、配置、导出器和必要守卫的实际变更通过相关检查后正常提交、合入并推送对应主分支，核对远端。无变化不造空提交，无Git项目仍可迁移但明确没有Git交付，不擅自建仓库。凭据不进入日志、模板或提交。

## 数据契约与映射

同一快照包含identity、publication、source_versions、management、milestones、metrics、issues、verification、delivery、completeness。它是可重建投影，不接管项目原始权威状态。现有21项管理字段与数值指标应来自这一快照；兼容消费者需要的形状由投影生成，不独立采集/手填第二份。

指标保留项目/指标ID、value或null、unit、dimensions、observed_at、business_at、source_ref/source_version、quality/reason、counting_basis；补充metric_kind、时间窗口/时区、scope_id、聚合规则及计数器重置语义。定义与展示说明放共享指标目录，不随每条数据重复复制。快照ID、导出器版本、源修订、内容指纹和数据覆盖可校验；Hub接收时间不覆盖业务时间。

公共维度为身份/目标、范围与进度、流程、产物、时间与积压、流入产能、质量返工、问题依赖、开发交付、运行、资源成本、数据质量。领域扩展按内容生产、软件/工具、学习、治理等profile启用；适用、未知、不适用、读取失败分别表达。只有有证据的事件或窗口统计才能计算吞吐/返工/时长，不能把净变化当真实产量；费用只来自实际记录。

计数使用稳定业务ID及有效版本，比例保留分子分母/范围变化，页/章/任务不混加，不能平均各项目百分比或P95。Git提交量不等于产品进度。未知或枚举错误只影响其依赖字段组；身份、权限或关键事务快照失败仍禁止使用依赖结果。

每个项目的数据映射必须对应：project_id→registry记录→声明/导出入口→source_ref及selector/query/function→metric_id/状态字段→转换、单位、维度、窗口、口径、缺失策略→源版本/验收证据。查询语句与业务函数由项目导出器执行；模板不运行任意shell/eval。项目/指标/源枚举映射以机器可读配置为权威，描述文字只解释。

现有metric_sources.yaml的选择、参数与源路径继续作为迁移基线；project_data_v3.yaml仅引用绑定位置，不复制它们。项目根和仓库身份来自registry/明确API绑定，不按目录名字猜仓库。旧STATE绝对路径若已过时，在该项目接入轮核对修复，不进行全目录搜索。

配置还包含中文名称/单位格式、关注指标、分组排序、目标期限、健康阈值与原因、状态映射、来源权威、适用性、同步有效期/超时、依赖/负责人与恢复链接、保留策略。公共默认集中维护，项目只覆盖差异。管理决定由明确来源维护，不由模型推测；业务发布到Hub，未来写回需单独接口，不双方改同一字段。

## 同步与运行契约

Hub启动先读已有本地投影，同时普通脚本发起一次同步；另支持手动同步、项目工作流结束发布。无需实时监听、消息队列或新常驻调度系统。模板只引用预登记导出入口及参数，统计过程不触发业务动作。

项目导出只读必要源，在临时文件完成校验后原子替换快照；以源版本/导出器版本避免无变化重复统计。Hub逐项目验证、事务导入，以请求/快照身份去重；中断后只续失败单元，不重写已成功事件。重复观察可以更新last_seen，不增加业务计数或重复历史快照。

单项目超时/离线不阻塞Hub启动及其他项目。保留latest_attempt、last_success及明确新鲜度；读取失败不能让旧成功冒充当前。标准快照有数量/字节边界与分页，原始素材和完整库不进Hub。模型摘要≤8KiB，机器统计不得为了该摘要限制丢分母或维度。

GitHub复用共享API客户端、显式仓库绑定、分页、ETag/有效期缓存及限流退避；同仓多个登记项共享请求，权限不足/限流/未完成分页输出明确覆盖缺口。远端事实绑定实际默认分支、提交和观察时间；本地引用不冒充联网验证，Actions成功不等于required checks齐全或脏工作区已测试。

## 每轮推进与完成依据

具体阶段、依赖、最小执行单元及逐项目分组在唯一静态路线表。阶段数不是会话数/工具次数，也不是保证完成所需轮数。每轮只读STATE当前游标、计划版本/摘要、该阶段和该项目映射；未变的路线全文与历史不要重复加载。可用普通Python/YAML选择字段，专用计划查询命令未实现前不得声称存在。

首次启动先选择V3-01；后续按依赖就绪且未验收的单元推进。某阶段有真实外部阻塞时，继续依赖已就绪的独立阶段/项目；全局收口仍保留未通过项。首次写入前按现有检查入口核对本单元，不靠重置任务ID、合同或预算绕过限制。

每单元完成：实现/配置→最近相关检查→差异复核→必要风险审查→对应仓库正常交付→更新STATE验收事实与一个下一步。不要等所有项目完成才提交，也不能只推Hub代替子项目。已有WIP按归属/用途/检查结果处理；无关产品重构不进入本计划。必要质量/保护检查不得绕过；无Git/无远端保持缺口，不自动新建或借Hub代交付。

STATE中每个验收单元记录稳定ID、版本、证据、交付/阻塞状态，项目粒度计数；静态路线不存进行中/完成状态。逻辑轮在发生实际实现、范围或证据变更并收尾时去重计数，工具/审查/状态询问不计新轮。沿用现有轮末进度规则，报告验收完成量、本轮执行/范围/证据变化、累计轮次及有置信度的剩余轮数区间；未知历史保留未知，不能从阶段数伪造累计轮数或重置用量。

停止浪费：确定性计数/映射/校验由程序做；禁止全仓/全历史/大报告注入、子Agent全历史继承、父子重复调查、无变化全测/重审、短间隔轮询、同失败无新证据重试。普通工作不强制三角色，不新增逐轮报告/收据/合同文件。跨仓只读调查可并行，写入/验证/交付串行；优先迁移复用，删除已被替代且无消费者的旧材料，不留新旧双维护系统。

最终验收必须包含所有登记处置、统一模板校验、两种真实项目导出、启动/手动同步、公共API与离线策略、审核阶段/返工回流/版本正确性及外置盘迁移、全项目映射覆盖、无Agent运行、历史/去重/错误隔离以及各仓交付。关闭未解决项需要真实证据或明确所有者范围决定；空项目不能偷偷从分母消失，部分完成不能标全部完成。没有图表或视觉验收项。
