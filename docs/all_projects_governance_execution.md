# 项目治理：数据前置能力

路线 v2；任务 ID 沿用 ALL-PROJECTS-CODEX-GOVERNANCE-V1，仅为历史关联，不限定执行工具。读者是项目维护者；目标、接口或验收改变时更新。修订或阅读本文不激活实施。本文替代本任务旧的全局 Agent 治理与逐轮文档审批路线。

## 目标与范围

项目事实 → 采集函数 → 校验与标准化 → 数值汇总和变化查询 → 精简输出 → 必要时模型分析。**本阶段不生成图表、不设计或改造 UI**，只使数据可供未来图表消费。文档、模板、治理状态完成都不等于项目接入完成。

不按 Codex/Cursor/人工来源区分治理资格。执行工具和作者只可作为审计元数据，不决定项目身份、指标、检查和交付。无需安装、启动或控制任何编辑器；全局 Agent/账号/模型/权限设置不是本阶段对象。可统一仓库内必要规则，保留实际文件归属及并发写入边界。

名单来自 data/registry/external_projects.yaml：沿用24个本地项目、2个 removed_local、17个云排除的已核实基线，运行时核对变化。云项目不治理；已移除项目保留身份与路径，禁读写扫描重试。无 Git、离线、缺源项目保留缺口，不自动移出分母。不创建新远端，不连接真实飞书，不调用未获费用授权的生成服务，不迁移存储、删除原始素材或操作凭据。

## 推进顺序

1. 复用现有 registry、连接解析/账本/CLI，实现公共程序采集与摘要接口。先报告已有指标和缺口，不由模型逐仓阅读全文计数；把公共路径/环境问题收敛为可测试的共因修复。
2. 先漫画，再一个异构项目（优先轻小说）贯通真实源→指标→汇总/变化查询→有限输出。复用漫画既有修复候选与验证，先使失败项和重做链可观测，再修复实际阻塞；不做图表。
3. 按相同接口覆盖其他本地项目。共用 Git/验证采集器，领域适配器只负责领域查询；由正常项目工作流更新事实，不让模型持续手填 STATE 或空模板。无业务计量的工具项目明确适用性，提供可验证功能里程碑/运行结果，不能以文档数量算进度。
4. 以数据测试收口并交付：关闭模型也能正常采集、校验、汇总、查询；飞书只准备禁用的本地字段映射/JSON样例。代码到各自主分支，不制造收据证明收据的循环。

## 函数能力与数据契约

以下是待实现能力，不声称现有命令已提供；优先复用已有模块，避免平行框架。

| 能力 | 确定性输入与结果 |
| --- | --- |
| 清单与身份 | registry、实际根/仓库身份；稳定project_id，在线/移除/无Git/缺源分别表达 |
| Git采集 | porcelain、numstat、refs、获授权的远端查询；分别统计暂存、未暂存、未跟踪、忽略、未推送及分支对主线差异，识别内容已在main；保留远端观察时间 |
| 业务指标 | 只读领域数据库、API、任务记录、manifest或程序生成状态；总量、阶段数量、完成/待审/失败/运行/待处理、积压年龄和处理速度 |
| 验证与交付 | 已有测试/CI结构化结果及绑定的代码/环境版本；提交、检查、推送、远端包含关系分开；采集不触发测试或部署 |
| 问题与恢复 | 稳定问题/任务ID、原因码、影响项、起止/更新时间、重试入口、恢复条件；读失败、业务阻塞、人工决定分开 |
| 汇总与变化 | 同project_id/metric_id/单位/范围的历史与变化；按项目/阶段/时间查询；下游直接消费数值JSON，不解析模型文字 |

项目业务、当前开发工作、治理接入、Git交付从各自真正的权威源派生，不是四套手填状态。允许不同事实来自不同源，保留字段依赖，不强迫所有数据塞入一个STATE文件。目标、优先级及人工决定引用已有明确记录，不能由计数猜出。

指标至少有project_id、metric_id、数值或null、unit、scope/维度、采集时间、业务时间（未知则null）、source_ref及版本/指纹、quality和原因。比例保留分子分母与口径；无分母不造百分比，页/章/测试等不同单位不混加。阶段计数明确是否互斥、是否按最新有效版本计算；稳定ID去重，旧版本不算新完成。历史不足时趋势为空，不虚构过去。

单字段未知/枚举错误不清空独立有效指标。权限拒绝仍禁止该源读取；关键身份或事务快照失败时，使其依赖组失效，不用局部成功放行关键失败。旧成功保留原时间，不能冒充当前成功。

采集只读且有限量，与项目写入/任务触发分开。按项目/来源版本、采集器版本失效缓存，远端按新鲜度复核；重复请求不重复业务事件，中断/重启可恢复。复用现有账本，不另建Goal调度器。默认摘要只有计数、变化、异常、下一步；明细分页，原始素材不进入模型或通用遥测。历史存储服务变化查询，明确粒度、保留和清理规则，不无限保存重复全快照。

## 漫画与同类卡点

沿已有真实失败ID与版本验证：反馈→重做资格→入队→领取→新候选→再送审。程序统计受影响集合、首次失败条件、各状态数量。先用真实失败记录的隔离副本复现，不能把合成测试称为实际图片重做。相关版本未变时复用现有候选与测试。

区分重新审核与要求重做；旧审核不批准新版本，重复事件不重复入队，新失败仍可合法重试。保护原始素材、已通过项和审核历史。真实生成依赖未授权费用/凭据时，完成独立可验证的数据与代码，明确保留实际重做未完成，不用mock冒充闭环；其他项目只复用经证实的共因。

## 严禁token浪费与重复流程

- 计数、比较、解析、去重、指纹、变化计算必须由程序完成。重复调查命令固化到现有采集器，不每轮重写清单。
- 禁止默认注入全仓、全历史、完整大报告、整库数据和测试长日志。先文件名/结构/摘要，再精确读取失败位置；长行先解析再摘字段。默认摘要≤8KiB，覆盖计数与错误数不可截掉，明细分页或按引用读取。
- 子Agent禁止继承完整历史（不得fork_turns=all）；只给目标、范围、版本、检查入口。无独立工作不派Agent，父子不重复调查。跨仓仅并行只读，写入/验证/交付按选定仓库串行。
- 复用绑定代码、输入、环境及检查版本的有效证据。没有相关变化或新失败，禁止重跑全量检查或重审相同候选。长任务保留原生句柄，等30–60秒或完成事件，禁止短间隔轮询反复推理。
- 同方法同失败连续两次无新证据，必须诊断或换方法。禁止靠增加合同、报告或Agent数量冒充进展；额度拒绝后无变化不重复调用，不改模型/额度绕过。
- 普通采集、局部修复、文档清理走实现→相关检查→一次差异复核。只有实际高影响行为或安全/控制边界变化才增加所需独立审查，不用三角色覆盖所有文件，不按编辑器要求专用角色。
- 不新增逐轮计划、合同、审查、安装、收据等平行文档。用Git差异/提交、程序结果和STATE一条恢复记录；普通交付元数据不触发新审查或收据的收据。
- 删除被替代说明、脚本、状态副本与无消费者产物前，核对引用、Git可恢复性、当前用途；修复活动引用，不创建归档副本或禁用测试隐藏依赖。未提交独有内容不得当历史垃圾丢弃。
- token只记可见遥测和口径，不估算账单，不把不可见值当0；未指定总预算时不伪造平台额度。必须有有界输出、证据复用、停止无效重试等可验证约束。消耗增长却没有数据接入、缺陷修复、有效验证或交付时，应收敛方法，不能继续堆说明。

## Git与验收

已有所有者授权覆盖原有未提交内容及本任务改动，按内容、用途与验证结果分单元，不按作者/编辑器划分。暂存、commit、push、CI、远端确认分别记录真实阶段与错误，不把未尝试说成GitHub拒绝。旧规则先判断适用性与新授权，实际权限/分支保护不得绕过。整体产品发布、公证、人审不自动阻止无关源码单元提交；相关必要质量检查必须通过。

从已核对主分支隔离混合历史，保护其他写者；正常提交推送各自真实主分支，保护分支走正式流程。核对提交被远端包含即为交付依据，main前进不触发收据更新循环；一次观察存原生结果或下次实质更新。无仓库/远端明确缺口，不借Hub代交付。

完成标准：
1. 每个登记项有处置；适用本地项目能从真实源获得业务数值/真实里程碑、问题及更新时间，不能只有治理complete或unknown空壳。离线/缺源/缺映射保持未完成，不自行减分母。
2. 关闭模型分析，清单、采集、校验、汇总、变化查询和JSON输出仍完整可用；指标可追溯，声明/采集器可校验，摘要有全部覆盖计数、明细分页。
3. 漫画与异构项目真实变化验证通过：源变化仅更新相关指标，重复刷新不新增业务项，重启可恢复；失败隔离、陈旧表达、计数口径通过测试。
4. 数据具有时间、单位、维度、质量和来源，可直接供未来图表消费；**无图表、UI或视觉验收要求**。飞书只完成禁用的本地数据映射。
5. 必要改动分别到各自主分支且远端已核实；冗余流程/文档已删除，无悬空活动引用；原有未交付项有归属及恢复点。实际重做等未解决项仍保留，不把部分完成报全部完成。

唯一管理入口为STATE.all_projects_governance，不恢复其他任务。AGENTS、该状态和本文是最小启动包，未变不重复加载历史。候选可直接登记STATE.candidate_paths，不需另建报告；最近相关检查通过后仅因新风险扩大检查，现有CI仍执行。只有发送Goal prompt才启动实施，不建立替代Goal的自动化。
