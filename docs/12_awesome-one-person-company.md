1. Build a life, not just a company——9 repo 对齐资产池思维。
2. 74.3% 成功创始人用 AI 为核心工具（与 solo-founder-playbook 呼应）。
3. Organic > Paid 3.5:1——小说/anime 优先 Build in Public。
4. 30 天清单用于每个新产品线 pilot。
5. 工具栈矩阵选 hosting/支付/分析（TTS 选 Railway/Fly.io）。
6. 商业模式六选一指导出版/TTS 组合策略。
7. AARRR 作为 dashboard 指标维度。
8. 中国 ICP/软著/微信支付宝清单用于国内发布 repo。
9. 案例模板写入 knowledge-base/competitors/。
10. Mom Test 作为新 repo 立项门禁（配合 ai-dev-os WIZARD）。
11. 硬资产（支付、域名、API 配额）集中 dashboard 管理。
12. 拒绝纯广告/未验证谣言的策展标准用于 lab catalog。
13. CC BY 4.0 商用需署名。
14. 与 awesome-claude-code 互补：商业 vs 工程索引。
15. 不能替代 Agent 协议或 Gate 实现。

## 7. 治理任务

1. 新产品线启动前对照 30 天清单 + Mom Test。
2. 选型时查工具栈矩阵。
3. 增长停滞查 AARRR。
4. 中国发布前 ICP/软著/支付合规。
5. 维护 lab 外部参考索引链接。
6. 每季度更新 catalog 中商业数据。
7. 记录自家跨 repo 复盘为 OPC 式案例。
8. 区分战略索引与执行 OS（勿混淆）。
9. IdeaLens 等关联产品批判性使用。
10. 与 solo-playbook 数据模式交叉验证。

## 8. 风险

- 策展非系统；信息会过时。
- 中国案例偏少。
- SaaS 偏见；game/content pipeline 需自定义。
- 无 Agent 治理层。
- 易停留阅读不落地。
