# Linux 网络维护

目标是恢复日常网页和 Codex 网络，并保持管理通道。单角色执行；用户当前指令决定权限和范围。Skill 提供操作方法，不授予系统修改权限，也不创建后台维护任务。

## 进入任务

先定位实际执行端：Mac、本机 Linux 或其他远端。跨 SSH 时重新核对主机身份、根盘 UUID、boot_id、时间、地址和管理连接回程；沿用已核验的主机密钥，变化或未知时停止敏感操作。只在安全交互终端输入密码，不读取或搬运登录会话。

读取已有项目入口和唯一状态文件，确认是否有任务正在修改重叠配置。普通项目进程不能当作网络修改者；不要强杀 Agent、apt 或 dpkg。先完成无冲突的只读工作。

仅在症状匹配时读取 [已验证故障与限制](references/incidents.md)：Wi-Fi/DNS、sing-box 更新后启动、sudo provider、SSH 重启后不可达。历史版本、IP、文件哈希是当时证据，不是未来兼容条件。

## 建立少量、有界的基线

- 找变化：指定修复记录或 Git diff、相关包安装记录，以及 NetworkManager、resolved、代理和内核的定向日志。过滤认证信息；不打印完整代理配置、账号缓存、环境变量或私人会话。
- Wi-Fi：接口、RSSI、频段、信道、协商速率、错误/重连和省电。天线没动仍不能排除信号变化；蓝牙共存干扰要有对照证据。
- DNS：resolv.conf 文件类型与目标、实际内容、resolved 路由，以及普通应用使用的 getent。服务 active 或 resolvectl 成功不代表应用解析正常。
- 路径：主路由、策略路由、管理连接回程、TUN、代理实际进程及必要的防火墙规则。UFW inactive 不代表没有其他规则。
- 局域网：定位实际互传工具、对端、监听地址与端口；检查当前直连网段、所需本地名称/发现机制和双向回程。结合策略规则、实际出口及必要的无载荷计数取证；普通 ip route get 或 SSH 成功不足以证明应用没有被 TUN 接管。不读取传输内容，不用大文件做压力测试。
- 功能：少量重复 DNS 与 HTTPS 请求，开启 TLS 验证并限制连接和总时长。curl 计时是累计值；阶段耗时分别计算 connect−namelookup、appconnect−connect、starttransfer−appconnect、total−starttransfer。

SSH 不可达时，先区分监听、主机地址、数据包路径与防火墙。ssh.service inactive 可能与 socket 激活有关；已监听仍超时要继续查路径，不盲目 enable 或改认证。只让用户补充无法远程取得的一条必要物理终端信息。

## 最小修复与更新兼容

一次改变一个有证据的主要变量。保存有限前像、权限和恢复办法，检查并发编辑。重连、重启网络/代理、改路由或防火墙前，先说明断线风险并核验不依赖 SSH 存活的本机回退；无法验证时等物理终端配合。

按实际配置格式、程序能力和运行错误决定兼容，避免把发行版、内核、软件版本或旧网段写成固定门槛。版本来自现有官方签名仓库；不要为追求 Mac/Linux 版本数字一致跨渠道安装。

已确认的本地互传应按当前连接/路由拓扑经局域网到达对端，同时保持需要代理的外网流量。仅修证据指向的 DNS、TUN 接管、规则优先级或回程问题；不要把全部私有地址一概直连，某些私有网段可能本来属于 VPN。新会话测试应覆盖互传两个方向、发现/连接和小型非秘密文件校验，防止只放行管理端地址却漏掉局域网应用。

sing-box 的配置检查通过后仍要核对真实启动与请求。只有确认出现对应运行错误时才改相关生成逻辑，并保留有效的分流和管理通道路由。

Codex 更新仅复用现有受限入口。应用、app-server、相关 Agent 运行或包管理锁繁忙时延期，不结束进程。保留签名、索引/包摘要、架构、依赖计划和保护检查。若默认 sudo 不支持现有命令摘要规则，验证已安装且支持该规则的 provider；不能删除摘要、扩大 NOPASSWD、增加备用认证或更改全局 sudo。

不自动重启，不进行全系统升级、驱动重装、凭据清空、全局关闭 IPv6/TLS/防火墙，不改 Mac VPN、VPS 或路由器。其他应用沿用现有更新方式。

## 验收与交付

核对普通应用 DNS、TLS 验证开启的 HTTPS、少量重复请求、必要代理路径、实际 Wi-Fi 状态、新的管理连接，以及实际局域网互传。语法、服务状态、网络传输和应用体验分别记录；401/403 可说明已收到 HTTPS 响应，不能证明 ChatGPT/Codex 已可用。

更新同一权威状态文件，记录原因与证据、改动、前后结果、回退、未验证项和唯一下一步。需要用户验收时集中为刷新一个网页及一次 Codex 操作。重启验收由用户决定；本会话恢复不等于重启验收通过。

同一方法两次没有新信息就换有依据的方法。原因不明时保留未排除项，不把重启恢复或时间先后当作根因。
