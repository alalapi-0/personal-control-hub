现在启动本项目的目标模式，按仓库里的飞书真实数据同步计划持续实施，直到全部验收完成。不要停在再次写计划、disabled 映射、mock 成功或一个试点成功。

目标：已登记且纳入范围的每个现存项目都有一个独立的飞书电子表格 Sheets 文件；一个总多维表 Bitable 能查看所有这些项目的真实管理数据、业务指标、问题和同步状态。源数据由项目程序产生，Hub 通过已有标准快照接入，程序调用飞书 API 发布并回读核验。日常采集、转换、更新、聚合、恢复和定时运行不能以模型、Agent、MCP 或人工搬运为必需环节。Agent 只用于开发与维护。

工作仓库是 `https://github.com/alalapi-0/personal-control-hub`。以最新 `origin/main` 为交付基线。先定位当前仓库与 task-owned Git 状态；同仓其他 worktree 或旧工作线不得覆盖。必要时从 origin/main 创建 `codex/` 前缀的独立同仓工作分支。Hub 保持本地，不把独立工作树当新项目注册，不迁移 Hub。原会话目录可能仍停在旧线，不能据旧 STATE 重新执行已完成 v3。

先读当前 checkout 的 `AGENTS.md` 和 `STATE.yaml`，然后读 `docs/feishu_project_cloud_sync_plan.md`。计划 ID 是 `FEISHU-PROJECT-CLOUD-SYNC-V1`，唯一当前执行状态是 `STATE.yaml#feishu_cloud_sync`；项目身份仍以 `data/registry/external_projects.yaml` 为准。只在当前单元需要时读 `docs/12_project_connections.md`、`data/connections/metric_sources.yaml` 与相关代码/测试。原 v3 已完成适用审计；保留其证据、65 轮历史和受限产品债，不从旧 v3 Prompt 开始，不恢复 Figma、存储迁移或其他治理任务。

本条启动指令授权本路线内的实现、必要验证、每轮将任务拥有改动提交并正常推送对应仓库 main。真实云写入仅限计划规定的真实项目投影和所有者已确认的飞书目标资源；先集中完成 H01–H07 的人工配置与授权边界，区分 configured 与实测 ready。身份、目标、字段、凭据和最小探针授权明确后，P01 可放行该探针；P03 完成 H03/H04 云实测，P07 完成 H07 调度实测，不把所有 H 项 ready 作为第一次云写的前置。对同一已批准范围不重复询问；登录、管理员审批、凭据录入、系统弹窗、付费、扩大权限或新敏感数据去向等只能本人完成/决定的动作，集中前置处理。不能从“有工具”推导出“有账户授权”。

首轮先做以下工作，再立即推进能完成的实现：

1. 核对最新 main 与 `STATE.feishu_cloud_sync`，认领本轮精确文件，记录风险 lane 和候选路径；首次写入前运行 `python3 scripts/auto_advance_runner.py --mode check --task-id ALL-PROJECTS-CODEX-GOVERNANCE-V1`。该旧 task-id 仅是当前仓库兼容检查入口，不是重新启动旧任务；它不授予飞书权限，也不验证新任务候选。P01 有界接入新任务 scope、STATE 选择、runner 候选范围、gate/policy 和一致性检查及测试，切换前直接核验本轮新候选。不能随便绕过 disabled gate。
2. 根据计划 P00 核对 required 项目集合和已接入证据，冻结 registry/来源版本与范围。26 登记＝24 本地＋2 removed 是计划基线，实施按当前有效证据更新。两个新项目没有登记/同步证据就延后，不补注册、不要求所有者先解释名字；有同步则按实际纳入。保留 removed_local、cloud exclusions、特殊读取路由和空业务处置。
3. 复用 `.hub/status.json` schema 2.0、原 import/SQLite 账本、`MetricStore.project_snapshot` 和 `python3 hub.py sync`。先看现有 `--help`，不要照抄计划中标为待实现的飞书命令并假称它们存在。不要重写已有 v3 采集、幂等收据或恢复系统。
4. 在第一个轮次交付具体人工准备包：H01–H07 待办、当时官方接口对应的精确权限清单、安全 Secret 录入入口、非秘密配置模板和 doctor。列出谁操作、位置、产物、程序验证和通过条件。准备完成再集中请所有者操作；等待期间继续 P02 与本地测试，不能把清单列完就停工。
5. 先验证 token 获取、API scope、应用发布、目标目录、文档与高级字段权限、所有者可见性、调度身份凭据访问，以及新文件权限继承。优先专用自建应用的应用身份；不依赖手工粘贴短期 token。所有 Secret/token 仅进入 OS/provider 凭据库或环境间接读取，不进入聊天、日志、命令参数、Git 或明文配置。不得读取浏览器 cookie 或公司账号资料。

然后按 P01–P08 的依赖推进：受治理的云准入与最小客户端 → 本地真实投影 → 一个真实项目两端闭环 → 增量/故障恢复 → 每项目串行覆盖 → 总 Base 对账 → 独立系统调度 → 真实运行观察与交接。人工前置不必阻塞独立纯本地单元，但关键依赖未通过不能验收下游。每次失败就在当前轮定位、修复并重验；外部阻塞给最小人工动作和恢复条件，继续其余项目。

云端结构和语义必须遵循计划：每项目独立 Sheets 文件；总 Base 的项目目录、项目指标、问题与缺口、同步状态都消费同一源快照投影。稳定 project_id/metric key，固定版本完整分页，保留字段口径、单位、窗口、源版本、quality 和原因；未知不填零，历史不冒充新鲜，治理完成不冒充业务完成。只上传批准字段，保留人工备注与非任务区域；不要复制原始作品/全文日志来证明“真数据”。

已有云资源先按 ID、归属和内容核对后复用；创建/写入结果不确定先 API 回读再重试。单目标串行，HTTP 200 非零业务码也算失败；支持限流、超时、部分失败、token 自动刷新、进程中断和映射恢复。一端成功不算整体成功；两端回读与同一源版本一致才完成该项目发布。项目数据消失/读取撤销需要历史或 inactive 标记，不永久保留成当前有效值，不清空用户表重传。

程序调度默认使用本机普通 Python + 用户级 launchd，每 15 分钟一次，机器开机且源可用时两个周期内收敛；关机/休眠不能保证实时同步，唤醒后补跑。安装前核对固定 Hub 路径、解释器、外置盘、后台权限和凭据。不要创建 Codex 定时任务来调用模型完成数据同步。最终以 P08 的实际观察证明关闭 Codex/Cursor/MCP/模型服务后仍可运行；不为了测试随意停止其他所有者的 Agent 任务。

范围只包括必要数据接入与云同步缺陷。不要借本目标启动原有未授权漫画返工、外盘迁移、历史 CI 修复、业务生成或受保护 WIP 清理。必须改项目导出器时，先进入唯一相关仓库读其规则并确认文件所有权；跨仓写入、验证、Git 交付串行。无 Git 项目不创建远程仓库，用 Hub 记录必要接入证据。

按当前全局风险规则分 DIRECT/REVIEWED/GOVERNED：普通实现和文档不套重复审批；云权限边界/控制面变更使用只读 Governor、Root 写控制面和登记证据、新 Judge 复核。子 Agent 仅做明确不重叠的有界任务，不自派生；Root 保有共享状态、外部写入和 Git 权限，轮末收集或精确停止所有后代，不留下后台 writer。

每轮以最小可审阅单元闭合：实施、相关检查、精确 diff 复核、更新同一 STATE、仅提交任务拥有文件、正常推 main、核对远端提交及适用 CI。不要只推工作分支而称 main 已交付；不强推、不绕过保护、不修改其他 checkout。主线前进就 fetch 并保留他人变更整合后重验。只有无法自行解除的权限/保护冲突才请求人工。没有文件变化不造空提交；每轮的检查和 git/远端事实构成证据，不生成一堆重复报告或自指 SHA 收据。

STATE 保存阶段、项目、H01–H07、A01–A09、范围/输入/候选版本、阻塞指纹、最新交付、去重执行轮数和唯一下一步。收到中断或上下文压缩时从这里续接，不重跑所有已验收项目。相同输入/版本/方法无新证据不重复；两次等价无进展后诊断或改方法。轮末使用实际存在的 goal-progress 技能做证据进度与轮次核算，task-health 仅在真实触发时使用；无遥测不编造 token/费用。
